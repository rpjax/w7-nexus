## Findings

### [HP-08-001] URL inexistente some no Início sem dizer que a rota não existe
- **Lentes:** gap | ux
- **Onde:** `/dashboard/nao-existe` (catch-all `*` → dashboard)
- **O que fiz:** autenticado, abri `https://nexus.websete.localhost:9143/dashboard/nao-existe`.
- **O que vi:** a barra foi para `/dashboard`. Título `Olá, admin`, item ativo **Início**. Nenhum “não encontrado”, toast ou aviso.
- **Por que dói:** deep link quebrado parece “o produto me mandou para casa”; o humano não sabe se errou a URL ou se perdeu permissão.
- **Sugestão:** página 404 interna no shell (mesmo chrome) com o path pedido e atalho para Início.
- **Severidade:** P2

### [HP-08-002] Toast de soma > 100% chega sem acentos
- **Lentes:** copy | polish
- **Onde:** `/dashboard/shareholders` → Salvar participação
- **O que fiz:** com total 47,5% (`minuteman` 35% + `qa08-share-130508` 12,5%), escolhi `adm`, pus 99%, confirmei.
- **O que vi:** toast de erro: `A soma das participacoes de Acionistas nao pode exceder 100%.` A lista não mudou (ainda 47,5%). A UI deixou tentar; o servidor bloqueou.
- **Por que dói:** o único aviso do limite parece texto de API crua no meio de toasts acentuados (`Participação salva.`).
- **Sugestão:** mesma frase no cliente, com acentos, alinhada ao restante do hub.
- **Severidade:** P2

### [HP-08-003] Diálogo “Remover participação” não diz quem sai
- **Lentes:** ux | copy
- **Onde:** `/dashboard/shareholders` → botão **Remover…**
- **O que fiz:** com duas linhas, cliquei o primeiro **Remover…** (era `minuteman`, não o `qa08-*` que eu tinha criado).
- **O que vi:** título `Remover participação`; texto `Remover esta participação da soma global de Acionistas.`; botões Cancelar / Confirmar / Fechar. Sem username nem %.
- **Por que dói:** fácil confirmar a linha errada; o diálogo de salvar *nomeia* a conta (`qa08-share-130508 passará a ter 12.5% do nível 2.`).
- **Sugestão:** repetir username + % no corpo, como no diálogo de salvar.
- **Severidade:** P2

### [HP-08-004] Empty states falam línguas diferentes

- **O que vi:**

  - Carteira: `Nenhum operador na sua carteira.`
  - Cobranças: `Nenhuma cobrança`
  - Claims: `Nenhum claim` + `Nenhum hop listado.`

- **Sugestão:** padrão “Nenhum(a) {coisa do título}.” + uma linha do que fazer depois.
- **Severidade:** P2

### [HP-08-005] Nav e H1 não usam o mesmo nome (Deals, Extrato, Perfil, Claims)
- **Lentes:** copy | ux
- **Onde:** shell vs `h1`
- **O que fiz:** cliquei a nav e li o título da página.
- **O que vi:**

  - Nav **Extrato** → H1 `Meu extrato`
  - Nav **Perfil** → H1 `Meu perfil`

- **Severidade:** P3

### [HP-08-006] Duas “Contas” no mesmo produto (login vs livro-mundo)
- **Lentes:** copy | ux
- **Onde:** nav **Pessoas → Contas** vs **Dinheiro → Livro-mundo** e coluna **CONTA** em Acionistas
- **O que fiz:** li Contas (`Identidades de login…`), Livro-mundo (`Contas de gateway, banco, crypto e payout…`) e Acionistas (coluna `CONTA` = username de login).
- **O que vi:** o humano usa “conta” para três coisas. Livro-mundo empty: `Nenhuma conta no livro-mundo.` Pessoas: `Contas`.
- **Por que dói:** chrome transversal mistura identidade e livro; glossário pede não colidir.
- **Sugestão:** nav Pessoas = `Identidades` (ou `Logins`); coluna de Acionistas = `Usuário`; empty do livro-mundo = `Nenhuma conta-mundo`.
- **Severidade:** P2

### [HP-08-007] Início de Admin usa kicker “ADMINISTRAÇÃO” no grupo Eu
- **Lentes:** polish | ux
- **Onde:** `/dashboard` H1 `Olá, admin`
- **O que fiz:** abri Início; item ativo **Início** sob **EU**.
- **O que vi:** badge `ADMINISTRAÇÃO` + subtítulo `Painel operacional: identidades, mandatos, cobrança, livro e rede.` Header do shell: `Websete Nexus` / `Painel operacional`. Avatar: `admin` · `Admin`.
- **Por que dói:** o grupo diz Eu; o kicker diz que a casa inteira é admin. Papel na UI é `Admin`, não `Administrator` (isso está ok e consistente com o diálogo Nova conta).
- **Sugestão:** kicker de Início = `Sessão` ou `Eu`, deixando `Administração` só nas telas de Pessoas/Dinheiro privilegiadas.
- **Severidade:** P3

### [HP-08-008] Loading some rápido demais para o humano ler; padrão de skeleton existe
- **Lentes:** polish | ux
- **Onde:** listas com tabela (Extrato, Acionistas, Contas, …)
- **O que fiz:** navequei ~15s por rota; não forcei throttle.
- **O que vi:** após o load, zero skeleton visível. Empty/listas já preenchidos. Não vi toast de loading. Confirms usam o mesmo padrão Cancelar / Confirmar (mais **Fechar** no canto do dialog).
- **Por que dói:** consistência de *estado* é boa quando há dados; o humano não vê “carregando” em rede rápida, então erros de rede vão parecer tela vazia se o empty disparar.
- **Sugestão:** manter skeleton (já parece existir) e empty só depois de resposta; erro de load distinto do empty (Acionistas já tem `errorMessage` na tabela).
- **Severidade:** P3

### [HP-08-009] Menu mobile abre/fecha e trava o body; overlay full-screen é difícil de acertar
- **Lentes:** ux | polish
- **Onde:** viewport ~390×844, botão **Abrir menu**
- **O que fiz:** estreitei a janela. Hambúrguer visível; sidebar desktop oculta. Abri o menu: `body overflow: hidden`; drawer `Menu de navegação` com os mesmos grupos Eu / Dinheiro / Pessoas + avatar `admin` / `Admin` + **Sair**. Fechei pelo X do drawer (ok). Clique no backdrop à direita também fechou. Destino **Perfil** fechou o menu e foi à rota certa.
- **O que vi:** o backdrop `aria-label="Fechar menu"` cobre a tela inteira por baixo do drawer; um clique “no meio” acerta um item da nav, não o overlay.
- **Por que dói:** scroll do fundo está correto; fechar “tocando fora” só funciona na faixa estreita à direita. Não é bloqueio.
- **Sugestão:** overlay só à direita do drawer, ou gesto swipe + X bem visível (o X já funciona).
- **Severidade:** P3
